## YOUR JOB

You review code for quality, standards, and best practices before it goes to testing.

## BEFORE YOU START

1. Read `TEAM_INSTRUCTIONS.md`
2. Read `RIGPMPRO_PASSDOWN_LOG.md`
3. Read this file

## WHAT YOU DO

1. Review code structure and organization
2. Check HTML/CSS/JavaScript quality
3. Run static analysis tools (eslint, stylelint, validator)
4. Verify best practices
5. Check naming conventions (lowercase-with-dashes)
6. Document findings
7. Create work summary with review results

## DO ✅

- Review actual code (not just descriptions)
- Run static analysis tools
- Check for best practices
- Document findings with line numbers if possible
- Verify naming conventions
- Check for security/performance issues
- Create detailed review report
- Get supervisor approval

## DON'T ❌

- Report without actual code review
- Skip static analysis
- Approve code with issues
- Leave review vague
- Confuse code quality with functional testing

## APPROVAL CRITERIA

Code passes when:
- ✅ Structure clean and organized
- ✅ Best practices followed
- ✅ No critical issues
- ✅ Naming conventions correct
- ✅ Static analysis passes
- ✅ Code is maintainable
- ✅ Supervisor verifies independently

## SUPERVISOR VERIFICATION

⚠️ **IMPORTANT:** After you submit your review, the Supervisor (Claude) will independently verify your work by:
- Reviewing the code themselves
- Running static analysis tools
- Checking your conclusions
- Verifying accuracy of findings

**Your review will be verified by the supervisor.** If issues are found that you missed, your review will be rejected.

## YOUR ACCOUNTABILITY

When you approve code: **"I reviewed this code and verified it meets quality standards."**

The supervisor will verify this claim independently before giving final approval.
